# 스테이지 바인더 v2 — 시카고 갈라반

하데스타운 갈라반 바인더를 복제해 시카고용으로 분리한 버전입니다. `C:\Users\user\cicago` 자료를 모두 넣었습니다.

## 들어 있는 내용

| 탭 | 내용 | 원본 |
| --- | --- | --- |
| 일정표 | 8회차, 회차별 진행 순서, 출결 | `시카고 일정.txt` |
| 동선표 | 이어지는 34개 대형 (CUE 번호 = PDF 쪽), 12명 + 스탠딩 마이크 | `Chicago 동선.pdf` |

| 문서 | 동선 PDF 보기 | `Chicago 동선.pdf` |
| 자료실 | MR 3곡, 동선 PDF, 큐시트 원본 | 원본 파일 |
| 설정 | 공연 정보, 멤버, 출결 명단 편집 | 관리자·초안 모드 전용 |

## v1과 달라진 점

- **큐시트 탭**: 가사·동작·마이크 셋팅을 처음부터 끝까지 이어서 보고, 검색하거나 내 큐만 볼 수 있습니다.
- **설정 탭**: 멤버, 명단을 코드 수정 없이 화면에서 편집합니다.
- **초안 모드**: 서버가 없어도 이 기기에서 편집·저장되고 `data.json`으로 내보낼 수 있습니다.
- **동선표 방향**: 동선 PDF와 같이 청중이 위, 격자와 번호도 PDF와 같습니다.
- **일정**: 회차별 진행 순서를 표시합니다. 끝 시각이 없으면 `18:00~`, 시간이 없으면 `시간 미정`으로 나옵니다.
- **하데스타운과 분리**: 서버 주소를 비우고 브라우저 저장 키도 나눠서 서로의 데이터를 덮어쓰지 않습니다.

## 자료가 바뀌었을 때

큐시트나 동선 PDF를 고친 뒤 다시 실행합니다. `pymupdf`가 필요합니다.

```bash
python tools/import_materials.py "C:/Users/user/cicago"
```

일정, 멤버, 곡 정보도 이 명령이 `data.json`을 새로 만듭니다. 화면에서 고친 내용은 초안이나 서버에 따로 저장되고, 그 저장본이 `data.json`보다 우선합니다. 단, 큐시트와 자료실, 문서는 항상 `data.json`을 따릅니다.

## 로컬에서 열기

MR과 PDF를 읽으려면 로컬 서버가 필요합니다.

```bash
python -m http.server 8765
```

브라우저에서 `http://127.0.0.1:8765`를 엽니다.

## 팀과 공유하기

1. 사이트는 GitHub Pages로 공개되어 있습니다: https://im-in-j.github.io/chicago-gala/ (가사와 MR 포함 전체 공개)
2. [apps-script/README.md](apps-script/README.md)대로 **새 Apps Script 프로젝트**를 배포합니다.
   하데스타운 서버 주소를 재사용하면 그쪽 동선·가사 데이터를 덮어씁니다.
3. `index.html`의 `var SERVER = ""`에 새 주소를 넣습니다.
4. 초안이 있다면 먼저 설정 탭에서 내보낸 뒤, 서버 연결 후 관리자로 로그인해 **불러오기** 합니다.
   서버를 연결하면 이 기기 초안은 더 이상 읽지 않습니다.
